# ATHRION

Fitness PWA: AI training plans, workout logging, calorie tracking, progress. Live at https://athrion.app.

## Stack
- React 18 + Vite 5 + Tailwind. Pages lazy-loaded in `src/App.jsx` (Workout is eager).
- Supabase: Postgres with RLS, Edge Functions (Deno), Storage, pg_cron. Project ref `dbpxxhqcsfypxjcdalca`.
- Vercel: static site + `api/` routes for Stripe (checkout, cancel, webhook). Checkout sells `monthly` / `annual` from `STRIPE_PRICE_MONTHLY` / `STRIPE_PRICE_ANNUAL` (live prices $4.99 / $49.99 since Oct 27 2026, before that $7.99 / $59.99; `scripts/move-to-new-prices.mjs` moves older subscriptions) with a 7-day trial for first-time subscribers. Displayed prices live in `src/lib/pricing.js` and must match Stripe.
- Claude API in `supabase/functions/generate-fitness-plan` (model `claude-opus-5-5`), `generate-meal-plan` (same `AI_MODEL`, structured output, logic in `meals.ts`) and `analyze-meal`.
- Capacitor wrappers in `android/` and `ios/` (not built yet; needs Xcode / Android Studio).

## Commands
- `npm run dev` · `npm test` · `npm run coverage` · `npm run build`
- `npm run icons` after adding any `mdi:` icon (icons are bundled offline in `src/lib/icons.json`; a test fails if one is missing)

## Deploying (always ask the user first)
- Site: `vercel --prod --yes` (CLI deploys; not connected to git).
- Functions: `supabase functions deploy <name>`; `send-reminders` needs `--no-verify-jwt` (cron calls it with `x-cron-secret`).
- Migrations: every applied one is in `supabase/schema.sql`, one section per original file in the order it ran (headings like `-- ═══ 011_notifications`; tests read sections with `sqlSection` in `tests/helpers/sql.js`). The live DB already has all of it; run it only on a new, empty project. A new change is `supabase/NNN_name.sql`: the user pastes it into the dashboard SQL editor (`supabase db query --linked` times out from Claude's shell), live DB changes need their explicit OK, and mind the order when the app and DB change together. Once applied, append it to the end of schema.sql under its own heading and delete the file. Admins are rows in `app_admins`. Not yet applied: 012 (`012_group_realtime.sql`, realtime for Train together rooms; rooms poll every 3 s anyway, and whether it ran is unverified). 022 to 025 (open reviews, lift goals, leaderboard distances, practices and meal plans) are applied and folded in.
- GitHub `Vorsee/Athrion` is PUBLIC. Working branch `progress-update-v1`. Never commit secrets (`.env.local` is ignored).
- Backup tags: `backup-2frame-demos`, `backup-old-design`.

## Conventions
- Dates: use `todayKey()` / `localDateKey()` from `src/lib/data.js`, never `toISOString().slice(0, 10)` (UTC bug).
- Train together (`pages/Group.jsx`) has Rooms / Leaderboard / Friends tabs (`components/Social.jsx`, `lib/socialApi.js`). Points are counted on the server (`month_points` in 009) and the rules are repeated in `src/lib/points.js`; change both together. On the 1st, `close_month()` saves the month; the top 3 on Everyone win a free month. Non-paying winners get `subscriptions.comp_pro_until`; winners paying through Stripe are handled by `api/monthly-prizes.js` (Vercel cron, daily 14:00 UTC, needs `CRON_SECRET`), which moves their next charge a month later via `trial_end`. `monthly_scores.prize_given_at` marks a prize as handed out. Pro = Stripe `status='pro'` or `comp_pro_until` in the future (`fetchProState` in `api.js`, both AI Edge Functions). Invite links: `/add/<nickname>`. New accounts pick a nickname as the first step of `pages/Onboarding.jsx` (suggested from their name, checked with `nicknameFree`), so they're on the leaderboard from sign-up; editing stats skips it. Free plan page: `/workout` (`pages/Guide.jsx`).
- Train together rooms are planned set by set: `group_sessions.plan` = `[{ name, sets: [{ reps, rest }] }]` (013), helpers in `src/lib/groupPlan.js`; rest is the seconds after that set, so a last set's rest is the break before the next exercise. Only the host edits the room. `saveSessionPlan` also writes `exercises` / `total_sets` / `rest_secs` for older clients.
- Coaches and the shop (014): `pages/Coach.jsx` (apply, dashboard, editor, admin review of applications), `components/Shop.jsx` (the Coaches tab, `pages/Coaches.jsx`), data in `src/lib/coachApi.js`. Coaches apply (`coach_profiles.status` pending → an admin in `app_admins` approves via `review_coach`), then publish `coach_products` (workout or 7-day plan, free or $2.99-$500). The listing (with `outline`) is public to signed-in users; `coach_product_content` (sets, tips, video paths) and the private `coach-videos` bucket (`<coach id>/<product id>-<time>.<ext>`) are readable only through `can_view_product` (owner, buyer, or free). `coach_profiles` has column grants: never `select('*')`, use `COACH_COLUMNS`. Paid sales: `api/coach-connect.js` (Stripe Connect Express onboarding, status, dashboard link) and `api/coach-checkout.js` (destination charge, `application_fee_amount` = `COACH_FEE_RATE` 20%, in `api/_coach-fee.js` and `src/lib/pricing.js`, a test keeps them equal). The webhook records `coach_purchases` for sessions with `metadata.kind = 'coach_product'` (and never treats them as Pro), and marks them refunded on `charge.refunded`. Bought workouts start like plan days (`toPlanDay` → `handleStartPlanDay`), carrying `coachTip` / `coachVideo` into `Workout.jsx` (`CoachNote`). Links: `/?open=coach`, `/?open=shop&product=<id>[&paid=1]`. Share links `/shop/<product id>` and `/shop/coach/<coach id>` (`src/lib/shopLink.js`): signed out they show `pages/ShopPreview.jsx`, fed by `api/shop-preview.js` (service key; published products of approved coaches only), and the link is kept in localStorage so it opens after sign-up.
- Swim (`pages/Swim.jsx`, `lib/swim.js`, `lib/swimApi.js`, 017): My swims (a tile per stroke, free/back/breast/fly/im, with PR pace, longest and last session; swims are `cardio_logs` with `stroke`) and Team. Starting a team takes an approved coach application: Team → Become a coach sends the same `coach_profiles` application as the shop, with specialty Swimming, and an admin approves it in Coach applications (also on Swim's Team tab for admins); then `save_swim_team` (018 checks `is_approved_coach()`); a coach lands on Team. The pool unit (metres / yards) is its own setting on this device (`readPoolUnit`), not the weight unit. Log a swim takes one swim or an interval set (`intervalSet`: reps × distance on a send-off; time = send-off × reps, so its pace never reads faster than it was). Landing's Start swimming goes through sign-up to Swim (`rememberSwimStart`). Swimmers join with the invite link `/swim/<code>` (straight in, remembered through sign-up) or find it in search (a request the coach accepts). The coach sees the roster with photos, a leaderboard per stroke and distance group (sprint / middle / distance, `DISTANCE_BANDS`) ranked by PR pace (`my_team_prs`, 020, per group from 024; `strokeBoard` in `lib/swim.js`, PR = fastest pace on a swim of 25 m or more, the same rule as the tiles), swimmer tiles with their 30-day volume, and each swimmer's swims (`swimmer_swims`), nothing else. All team reads and writes go through the 017 functions. `swimming` is also a plan goal (`nutrition.js` and `plan.ts`; redeploy `generate-fitness-plan` for it).
- Plan is a progress tab, not a second workout page: at the top `GoalCard` (`components/GoalProgress.jsx`): a ring (weight goals: share of the way from start to target weight, `goalProgress` in `lib/weightGoal.js`; other goals: planned workouts done, `planProgress` in `lib/planProgress.js`), start and target dates, days left, on track or behind, now / done / to go, and this week Monday to Sunday. Then a one-row Today with Start, the week card, `ResultsCard` (workouts, volume, weight change, the weight chart with a dashed goal line, and a dated timeline). Free users see their own goal card and results above a sample plan behind the lock, built for their goals and days by the server's fallback (`sampleFor` in `lib/samplePlan.js` imports `makeFallbackPlan` from `plan.ts`). Days before the goal started never count as missed. Goal and weight changes go through `GoalSheet` / `WeightSheet` (a weigh-in is a `body_measurements` row plus the profile weight).
- Weight goals: lose / gain weight ask for a target weight and a pace (`components/WeightTarget.jsx`) in the first plan question and in `GoalSheet`. `weightPlan` turns them into a weekly rate (loss 0.5-1%, gain 0.25-0.5% of body weight a week), a daily calorie change (3,500 kcal per lb, at most -1,000 / +500, never under `MIN_CALORIES`, and then the date moves out), and a target date; `calculateNutritionTargets({ goalAdjustment })` uses that change. Targets under a BMI of 18.5 are refused. Saved: `target_weight_lb`, `goal_pace`, `goal_start_weight_lb`, `goal_start_date` (every goal), `goal_target_date` (021).
- Two goals (`lib/goalPick.js`): the plan questions and `GoalSheet` take one goal or two that go together; lose, gain and maintain weight never pair. A weight goal leads (`primary_goal`, it sets calories and the ring), the other is `secondary_goals`, sent to the plan as `secondaryGoalProgramming`. Lift targets show whenever either goal is a lift goal.
- Lift targets (023, `lib/liftGoals.js`): for build muscle, improve strength and gain weight, `GoalSheet` sets up to 3 of `KEY_LIFTS` with today's best set of 5 and a target; `bestSet` reads the log (matching common names, e.g. "Barbell Bench Press" counts as Bench Press) and the goal card's ring becomes the average progress. They go to the plan prompt as `keyLifts`.
- Plans train legs and include cardio: `SYSTEM_PROMPT` and the build_muscle `GOAL_PROGRAMMING` in `plan.ts` require lower body at least as often as upper, a weekly cardio session, and plain exercise names; the fallback uses `MUSCLE_SPLITS` per training-day count (legs at least twice) and an "Easy Cardio" day for muscle and strength goals. Redeploy `generate-fitness-plan` after changing them.
- Library: 213 exercises in `EXERCISES` (`src/lib/data.js`), muscle groups in `MUSCLES` include Calves and Cardio (treadmill, bike, elliptical, stair climber, intervals); timed ones use reps like "20-30 min".
- Food → Meal plan (`components/MealPlan.jsx`, `lib/mealPlan.js`): a day of everyday foods in grams sized to the person's calories and protein (protein foods to the meal's protein, carbs and fats fill its calories, then shrunk if it runs over), respecting the diet (vegetarian, vegan, halal has no pork in the list anyway, fasting gets two meals and a snack), which the plan questions set and the meal plan's chips change (`saveDiet`; on the device until there's a fitness profile). Swap a meal or log it to today.
- Reviews (021, 022, `lib/reviews.js`, `components/Reviews.jsx`): anyone can write one on the landing page without an account (`api/review.js`: honeypot, no links, 2 a day per hashed address, 40 waiting an hour overall); those are saved hidden and every admin gets a `review` notification to approve them. Signed-in people write one each in You → Rate ATHRION, posted straight away, shown on the landing page with the average (before the first one, the section invites one). Signed out, RLS returns only shown reviews and no ids. Admins hide or show reviews from the same screen (a trigger stops writers unhiding their own). The privacy policy covers reviews and swim teams (section 5).
- Notifications: every event is a row in `notifications` (the header bell, `components/NotificationsSheet.jsx`, `lib/notifications.js`), written by database triggers in 011 (friend request/accept, badge, 12-day target, month result) and 019 (swim team requests, joins, answers, leaving; coach applications to every admin). Rows with `push` true are pushed by `send-reminders` (`{ deliver: id }`), which also sends the daily reminder with a short summary and the Sunday recap (hourly cron), and "your workout is still open" (`{ open: true }`, every 15 min) from `open_workouts`, which `Workout.jsx` mirrors via `syncOpenWorkout`. Per-type push switches are `reminder_settings.notify_*`. A notification links to `/?open=friends|ranks|workout|progress|notifications|swim|team`, handled by `openTarget` in App. Badge names are repeated in 011 (a test checks them against `lib/badges.js`).
- Coaching on the Pro plan (`lib/coaching.js`, all from the log, no AI call): each plan exercise shows next session's target (`nextTarget`, the same double progression as Workout's `suggestNext`), every 5th week of the goal is lighter (`isDeloadWeek`: one set less, ~80% weight, carried into Workout as `deload` on each exercise), missed workouts this week move to the next free days (`reshuffleWeek`, display only), and `CoachCard` on Plan shows `weeklyReview` (what went well, what to change, on track or behind; "Your weekly review" on Sundays). Swims (cardio_logs) count as done training days on Plan.
- Pool sessions in plans: when swimming is a goal, plan days have `sport: 'swim'` with sets as exercises ("Main set: freestyle", sets = repeats, reps = "100 m on 1:50"); `swimSessions` in `plan.ts` is the fallback; `generatePlan` sends `swimPaces` from the person's swims. Swim days open Swim instead of Workout. Stroke progress charts on My swims are Pro.
- Team practices (025, applied): the coach posts a day's warm-up / main / cool-down (`CoachPractices`, `PracticeEditor` in `Swim.jsx`, templates and totals in `lib/swim.js`); every active swimmer gets a `team_practice` notification (push follows `notify_team`) and sees it on Team (and a row on My swims), with "I swam it, log it" saving one swim.
- Food → Meal plan: Pro gets the AI week (`components/AiMealPlan.jsx`, `lib/mealPlanApi.js`: likes, dislikes, cook time, diet chips; 7 days, steps, shopping list, log a meal); free keeps the one-day `MealPlan` with a Pro card.
- Pro features are gated twice: UI (`components/ProLock.jsx`, or an inline Pro tag), and server-side in the Edge Function. Pro = AI plan with coaching, pool workouts and stroke charts, AI meal plan, adaptive targets, AI photo meal scan, unlimited saved workouts; one list in `PRO_FEATURES` (`src/lib/pricing.js`). Calorie logging, barcode and targets are free. "Get Pro" opens `UpgradeSheet` (`goUpgrade` in App), which then goes to Stripe.
- Weights are stored in lb everywhere; show and read them through `useUnit()` / `fromLb` / `toLb` in `src/lib/units.js` (the person's `weight_unit`), never hardcode "lb".
- Large text: Chrome on Android zooms the page for big phone text, so layouts must hold at 240px (150%) and 288px (125%) wide with no sideways scroll. Rows wrap their figures and buttons under the name (`ExerciseRow`), tiles and button pairs use `repeat(auto-fit, minmax(min(100%, …), 1fr))`, `Button` grows with wrapped text (min-height, not fixed height).
- Design: sentence-case text, no emoji in UI, `mdi:` line icons, text 12px minimum (`text-2xs` 11px only for chart axes and tags), no glows. Colours are CSS variable tokens in `src/index.css` (dark on `:root`, light on `.light`), used through Tailwind names (`bg-surface`, `text-ink`, `text-muted`, `text-neon-ink`…); no raw hex or `text-gray-*` in JSX. Neon `#C8F135` stays the accent. Shared building blocks are in `src/components/ui/` (`PageHeader`, `ExerciseRow`, `ActionRow`, `BigNumber`, `StatTiles`, `InfoButton`/`Fact`): big title with neon fact chips, one-line rows, explanations behind ⓘ rather than on the page; spec and rubric in `.design/` (gitignored).
- Brand is written "ATHRION" everywhere in the UI.
- Bottom nav has 5 tabs: Train, Plan, Food, Progress, Swim (page keys `workout`, `plan`, `calories`, `progress`, `swim`); admins (`app_admins`, `fetchIsAdmin`) also get Coaches (`shop`) as a sixth while the shop is built, and `ADMIN_PAGES` in App keeps `shop` / `coach` and their links from everyone else; below 320px wide the labels are icon-only. Library and Group open from Train, the coach page from Coaches (`PARENT_TAB` in `components/Nav.jsx`). The Train together card on Train has a big Train together button (opens Rooms) and smaller Friends / Leaderboard buttons, each opening Group on that tab (`onOpenGroup` → `groupIntent`); Group's default tab is Friends. Pushed sub-screens use `useBackHandler` from `src/lib/shell.js` (header back and the phone's back gesture), not their own back buttons.
- The exercise demo animation is commented out on purpose in `ExerciseDemo.jsx` until an ExerciseDB HD licence is bought.
