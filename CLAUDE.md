# ATHRION

Fitness PWA: AI training plans, workout logging, calorie tracking, progress. Live at https://athrion.app.

## Stack
- React 18 + Vite 5 + Tailwind. Pages lazy-loaded in `src/App.jsx` (Workout is eager).
- Supabase: Postgres with RLS, Edge Functions (Deno), Storage, pg_cron. Project ref `dbpxxhqcsfypxjcdalca`.
- Vercel: static site + `api/` routes for Stripe (checkout, cancel, webhook). Checkout sells `monthly` / `annual` from `STRIPE_PRICE_MONTHLY` / `STRIPE_PRICE_ANNUAL` (live prices $4.99 / $49.99 since Oct 27 2026, before that $7.99 / $59.99; `scripts/move-to-new-prices.mjs` moves older subscriptions) with a 7-day trial for first-time subscribers. Displayed prices live in `src/lib/pricing.js` and must match Stripe.
- Claude API in `supabase/functions/generate-fitness-plan` (model `claude-opus-5-5`), `generate-meal-plan` (same `AI_MODEL`, structured output, logic in `meals.ts`) and `analyze-meal`.
- Capacitor wrappers in `android/` and `ios/` (not built yet; needs Xcode / Android Studio).

## Commands
- `npm run dev` · `npm test` · `npm run coverage` · `npm run build`
- `npm run icons` after adding any `mdi:` icon (icons are bundled offline in `src/lib/icons.json`; a test fails if one is missing)

## Deploying (always ask the user first)
- Site: `vercel --prod --yes` (CLI deploys; not connected to git).
- Functions: `supabase functions deploy <name>`; `send-reminders` needs `--no-verify-jwt` (cron calls it with `x-cron-secret`).
- Migrations: every applied one is in `supabase/schema.sql`, one section per original file in the order it ran (headings like `-- ═══ 011_notifications`; tests read sections with `sqlSection` in `tests/helpers/sql.js`). The live DB already has all of it; run it only on a new, empty project. A new change is `supabase/NNN_name.sql`: the user pastes it into the dashboard SQL editor (`supabase db query --linked` times out from Claude's shell), live DB changes need their explicit OK, and mind the order when the app and DB change together. Once applied, append it to the end of schema.sql under its own heading and delete the file. Admins are rows in `app_admins`. Not yet applied: 030 (`030_delete_swim_team.sql`, `delete_swim_team()`: a coach deletes their team from the bottom of Team, typing its name to confirm; swimmers are told, practices go, swims stay; before it runs the button shows an error). 029 (`029_fair_points.sql`, `month_points` counts only workouts saved within 2 days of their date, so imports and older past-day logs earn no points; `points.js` already says so). 028 (`028_more_badges.sql`, badge notification names for the new badges; before it they read "New badge"). 012 (`012_group_realtime.sql`, realtime for Train together rooms; rooms poll every 3 s anyway, and whether it ran is unverified). 022 to 027 (open reviews, lift goals, leaderboard distances, practices and meal plans, swim names and free meal scans, teammates) are applied and folded in.
- GitHub `Vorsee/Athrion` is PUBLIC. Working branch `progress-update-v1`. Never commit secrets (`.env.local` is ignored).
- Backup tags: `backup-2frame-demos`, `backup-old-design`.

## Conventions
- Dates: use `todayKey()` / `localDateKey()` from `src/lib/data.js`, never `toISOString().slice(0, 10)` (UTC bug).
- Train together (`pages/Group.jsx`, its own bottom-bar tab "Together") has Rooms / Friends / Leaderboard tabs (`components/Social.jsx`, `lib/socialApi.js`). Points are counted on the server (`month_points` in 009) and the rules are repeated in `src/lib/points.js`; change both together. On the 1st, `close_month()` saves the month; the top 3 on Everyone win a free month. Non-paying winners get `subscriptions.comp_pro_until`; winners paying through Stripe are handled by `api/monthly-prizes.js` (Vercel cron, daily 14:00 UTC, needs `CRON_SECRET`), which moves their next charge a month later via `trial_end`. `monthly_scores.prize_given_at` marks a prize as handed out. Pro = Stripe `status='pro'` or `comp_pro_until` in the future (`fetchProState` in `api.js`, both AI Edge Functions). Invite links: `/add/<nickname>`. New accounts pick a nickname as the first step of `pages/Onboarding.jsx` (suggested from their name, checked with `nicknameFree`), so they're on the leaderboard from sign-up; editing stats skips it. Free plan page: `/workout` (`pages/Guide.jsx`).
- Train together rooms are planned set by set: `group_sessions.plan` = `[{ name, sets: [{ reps, rest }] }]` (013), helpers in `src/lib/groupPlan.js`; rest is the seconds after that set, so a last set's rest is the break before the next exercise. Only the host edits the room. `saveSessionPlan` also writes `exercises` / `total_sets` / `rest_secs` for older clients. A room can instead be a free workout: the host picks sets per exercise (2-5) and rest (30-120 s) as on Train's free workout, saved as `plan = [{ free: true, sets }]` (`freePlan` / `freeRoom`, no new column; `planFrom` leaves it out); everyone then picks their own exercises on a picker (`PickerScreen`), kept locally (`myPlan` in the saved room state), and `standings({ free })` has no total to finish.
- Coaches and the shop (014): `pages/Coach.jsx` (apply, dashboard, editor, admin review of applications), `components/Shop.jsx` (the Coaches tab, `pages/Coaches.jsx`), data in `src/lib/coachApi.js`. Coaches apply (`coach_profiles.status` pending → an admin in `app_admins` approves via `review_coach`), then publish `coach_products` (workout or 7-day plan, free or $2.99-$500). The listing (with `outline`) is public to signed-in users; `coach_product_content` (sets, tips, video paths) and the private `coach-videos` bucket (`<coach id>/<product id>-<time>.<ext>`) are readable only through `can_view_product` (owner, buyer, or free). `coach_profiles` has column grants: never `select('*')`, use `COACH_COLUMNS`. Paid sales: `api/coach-connect.js` (Stripe Connect Express onboarding, status, dashboard link) and `api/coach-checkout.js` (destination charge, `application_fee_amount` = `COACH_FEE_RATE` 20%, in `api/_coach-fee.js` and `src/lib/pricing.js`, a test keeps them equal). The webhook records `coach_purchases` for sessions with `metadata.kind = 'coach_product'` (and never treats them as Pro), and marks them refunded on `charge.refunded`. Bought workouts start like plan days (`toPlanDay` → `handleStartPlanDay`), carrying `coachTip` / `coachVideo` into `Workout.jsx` (`CoachNote`). Links: `/?open=coach`, `/?open=shop&product=<id>[&paid=1]`. Share links `/shop/<product id>` and `/shop/coach/<coach id>` (`src/lib/shopLink.js`): signed out they show `pages/ShopPreview.jsx`, fed by `api/shop-preview.js` (service key; published products of approved coaches only), and the link is kept in localStorage so it opens after sign-up.
- Cardio (`pages/Cardio.jsx`, the `swim` page): a Swim / Run switch, the last one remembered on the device (`athrion_cardio_sport`); the first visit opens Run unless swimming is a goal or they've only swum (`firstSport`); a swim intent (invite, team notification) opens Swim. Run (`pages/Run.jsx`): this week (distance, runs, time), best pace (runs of 1 km+) and longest, a pace chart (free), Log a run (a sheet: distance in km or mi by the weight unit, time, date, notes), recent runs with share and delete; runs are `cardio_logs` with `kind = 'run'` (015 already allows it), share cards take `kind: 'run'`. Runs and swims count as done training days on Plan and Train (`cardioAsHistory` in `lib/coaching.js`). Plans use runs: `generatePlan` sends `recentRuns` (`runSummary` in `lib/cardio.js`: last 8 weeks, runs a week, weekly km, longest, best and recent pace per km, usual run days, days since the last run) for every goal; `SYSTEM_PROMPT` keeps their runs (a run-only day has `sport: 'run'`), counts them as the week's cardio and keeps hard leg days away from long runs; the fallback's easy cardio day becomes an easy run (`runDay`). Run days show "Log this run" on Train and "Log run" on Plan, opening Cardio on Run (`rememberCardioSport`). Redeploy `generate-fitness-plan` after changing this.
- Swim (`pages/Swim.jsx`, inside Cardio with `embedded`, which drops its own title; `onSubScreen` tells Cardio to hide its title and switch while a swimmer's page or the applications are open; `lib/swim.js`, `lib/swimApi.js`, 017), kept minimal: My swims is a card per stroke (PR pace, last swum), one Log a swim button (a sheet), and the opened stroke's pace chart (Pro) and swims, else recent swims; swims are `cardio_logs` with `stroke`. A swimmer's Team: their team card (settings sheet: name, photo, show to teammates, leave), today's practice, teammates by 30-day distance and Team results (best paces; `my_teammates` / `my_teammates_prs`, 027). A swimmer is shown to teammates only while `show_to_team` is on (off for those who joined before 027, on for new ones). Team. Coach tools are free. Starting a team takes an approved coach application: Team → Become a coach sends the same `coach_profiles` application as the shop, with specialty Swimming, and an admin approves it in Coach applications (also on Swim's Team tab for admins); then `save_swim_team` (018 checks `is_approved_coach()`); a coach lands on Team. The pool unit (metres / yards) is its own setting on this device (`readPoolUnit`), not the weight unit. Log a swim takes one swim or an interval set (`intervalSet`: reps × distance on a send-off; time = send-off × reps, so its pace never reads faster than it was). Landing's Start swimming goes through sign-up to Swim (`rememberSwimStart`). Swimmers join with the invite link `/swim/<code>` (straight in, remembered through sign-up) or find it in search (a request the coach accepts). The coach sees each swimmer by the name they chose for the team (`display_name`, 026, set when joining or on Team; `swimmerName` falls back to @nickname), the roster with photos, a leaderboard per stroke and distance group (sprint / middle / distance, `DISTANCE_BANDS`) ranked by PR pace (`my_team_prs`, 020, per group from 024; `strokeBoard` in `lib/swim.js`, PR = fastest pace on a swim of 50 m or more (`PR_MIN_M`), the same rule as the tiles and `cardioSummary`), swimmer tiles with their 30-day volume, and each swimmer's swims (`swimmer_swims`), nothing else. All team reads and writes go through the 017 functions. `swimming` is also a plan goal (`nutrition.js` and `plan.ts`; redeploy `generate-fitness-plan` for it).
- Plan is a progress tab, not a second workout page, titled "Personal trainer" (no plan-name header, no calorie card, no safety or advice cards on Pro): at the top `GoalCard` (on Pro it animates: the ring sweeps and counts up, done days pop in, lift bars grow, and a quarter / half / three quarters / goal milestone shows once per goal, kept in `athrion_milestone_<start>`), then `TipCard`, the personal coaching tip (`plan_data.coachingTip` written by the AI with each plan and weekly adapt, else `personalTip` in `plan.ts`: beginners are told to start light and build), then a one-line `CoachCard` (headline, the best thing, the one change, moves; "Full review" opens the rest). The goal card (`components/GoalProgress.jsx`) has a ring with a dot for where the pace puts you today (weight goals: share of the way from start to target weight, `goalProgress` in `lib/weightGoal.js`; other goals: planned workouts done, `planProgress` in `lib/planProgress.js`), the goal date (`goal_target_date`, else the plan's end; the timeline uses the same), days left, on track or behind, now / done / to go, and this week Monday to Sunday. Then a one-row Today with Start, the coach card, the week, the weekly check-in, `ResultsCard` (workouts, volume, weight change, the weight chart with a dashed goal line, and a dated timeline). Free users see their own goal card, the coaching tip and results, then the Pro card (`ProLock`, in the page flow) above a faded sample plan (three things Pro adds, the price, when the trial charges), built for their goals and days by the server's fallback (`sampleFor` in `lib/samplePlan.js` imports `makeFallbackPlan` from `plan.ts`). Days before the goal started never count as missed. Goal and weight changes go through `GoalSheet` / `WeightSheet` (a weigh-in is a `body_measurements` row plus the profile weight).
- Weight goals: lose / gain weight ask for a target weight and a pace (`components/WeightTarget.jsx`) in the first plan question and in `GoalSheet`. `weightPlan` turns them into a weekly rate (loss 0.5-1%, gain 0.25-0.5% of body weight a week), a daily calorie change (3,500 kcal per lb, at most -1,000 / +500, never under `MIN_CALORIES`, and then the date moves out), and a target date; `calculateNutritionTargets({ goalAdjustment })` uses that change. Targets under a BMI of 18.5 are refused. Saved: `target_weight_lb`, `goal_pace`, `goal_start_weight_lb`, `goal_start_date` (every goal), `goal_target_date` (021).
- Two goals (`lib/goalPick.js`): the plan questions and `GoalSheet` take one goal or two that go together; lose, gain and maintain weight never pair. A weight goal leads (`primary_goal`, it sets calories and the ring), the other is `secondary_goals`, sent to the plan as `secondaryGoalProgramming`. Lift targets show whenever either goal is a lift goal.
- Lift targets (023, `lib/liftGoals.js`): for build muscle, improve strength and gain weight, `GoalSheet` sets up to 3 of `KEY_LIFTS` with today's best set of 5 and a target; `bestSet` reads the log (matching common names, e.g. "Barbell Bench Press" counts as Bench Press) and the goal card's ring becomes the average progress. They go to the plan prompt as `keyLifts`.
- Plans train legs and include cardio: `SYSTEM_PROMPT` and the build_muscle `GOAL_PROGRAMMING` in `plan.ts` require lower body at least as often as upper, a weekly cardio session, and plain exercise names; the fallback uses `MUSCLE_SPLITS` per training-day count (legs at least twice) and an "Easy Cardio" day for muscle and strength goals. Redeploy `generate-fitness-plan` after changing them.
- Train for free accounts: no plan and no saved workout, Today shows the starter sessions for their goal and place (`starterSession` in `Workout.jsx`: the free plan's `guidePlan` scheme, lose weight → fat, muscle / strength / gain → muscle, else fit; home or gym), A → B → C, the same for Pro without a plan; with saved workouts, one comes up per day (`dayPick`, the same all day).
